# Skynet + MoonChipmunk 服务端 POC 报告

## 结论
- **能否直接集成？** 原版不能。以《磁力小车》锁定的 Skynet 所带 Lua 5.5.1 头文件编译时，原版 MoonChipmunk 的 `compat-5.3.h` 拒绝新 Lua。仅放宽版本判断也解决不了进程级共享状态。原版失败输出在 `logs/native-moonchipmunk-original-build.log`。
- **是否需要改源码？** 需要。本 POC 的补丁让 5.3 与以上版本使用原生 Lua API；将 allocator、枚举字典、userdata 索引和临时状态移至各 Lua VM 独立上下文，把当前调用的上下文放入线程局部并在受保护的调用边界恢复。上下文属于 Lua VM，不绑定某一个 Skynet worker。禁用了本次不验证的 Hasty Space。实际服务 `require`、建 Space、单步并读取位置成功。
- **多个 Room Actor 的隔离？** 通过此 POC 的带断言路径。A/B 并存，A 碰撞回调正确区分车 ID，B 状态不受影响；注入 A 的 Lua RPC 错误后 B 保持原值；A 退出、重建 24 次后，B 自己的回调仍能运行。服务退出另外用独立 RPC 心跳验证。C 崩溃可能带走整个 Skynet 实例；没有做代码覆盖、线程/地址 sanitizer、原生回调异常恢复或长期泄漏证明。
- **20 Hz 还是 60 Hz？** 建议《磁力小车》先保留 20 Hz 时钟和 10 Hz 同步。两档均覆盖 8 项物理用例；这轮未验证真实最高速/冲刺参数下 20 Hz 的穿透边界。若玩法需要更硬更窄的车体或高速碰撞，先回放真实输入、找出穿透/抖动工况，再考虑只对物理子步升到 60 Hz，不同步提高网络广播频率。
- **是否现在正式引入？** 不建议直接替换现有碰撞。可先在独立分支做离线对照回放和可关闭的候选后端；匹配手感、击退、眩晕、电池掉落、同步及断线重连后，再决定是否小流量试运行。正式采用前补压力长跑及 native 资源验证，把 Lua 回调异常改为 step 返回后报告，避免跨求解器 C 栈直接传播错误。

## 固定的测试环境和构建
详见 `deps.lock`。磁力小车 commit `e4c7af9`；锁定的 skynet-demo commit `f1baee5`，镜像 manifest `sha256:9cbaa652cb9f37b8f6025a54d76d9fd18315852c70653b038be972ee074b2d8c`；Skynet `64391f7`（Lua 5.5.1，复用 bundled jemalloc，应用镜像里的已验证 TLS + socket flow control 源码补丁）。MoonChipmunk `0e93b01`（0.1），Chipmunk2D `f2f3d66`（7.0.3）。使用 Skynet 仓库 Lua 头文件且不链接独立系统 Lua，Lua 符号由 Skynet 进程解析。
Linux x86-64 / Debian 13 / GCC 14.2 / glibc 2.41。云环境可见 AMD EPYC 9V74、9 vCPU、约 9.7 GiB 内存；Skynet 4 worker。VM 视野并不等于独占主机资源；cgroup 配额不可见。C 绑定与 Chipmunk GCC `-O2 -fPIC -shared`，Chipmunk `-DNDEBUG`，Skynet 使用同源码的原生 Makefile。此 POC 没启动原游戏/原镜像；并不宣称原生二进制和镜像逐位一致。Docker 与 ARM64/macOS 原生、H5、微信小游戏客户端均未验证。

## 如何复跑
用空构建目录重新下载锁定依赖，执行 `./build.sh && ./smoke.sh && ./run.sh test`，三个命令均退出 0。干净复跑日志见 `logs/clean-reproduction/`。
见 `README.md`。压测每组重新启动 Skynet，每个 Room 独立 8 个模拟车辆。先让房间都就绪，再共用同一单调钟开始时间；同相位起步可形成调度突发。20/60 Hz 都用固定 dt，使用 Skynet 的 10 ms timer 唤醒并做限量追赶，不以 sleep 精度代替仿真时间。每组 60 秒，同时 10 Hz 提取并检查位置、速度和角度。完整日志包含每个 Room 的步进计数及直方图、清理后时间戳和进程 CPU/RSS 时间序列。

**读数定义：** 步进包含 Lua 车辆控制与求解；求解包含绑定调用和 C 回调回 Lua 的时间（纯 Lua 基线则是项目碰撞函数及其回调），两者都使用墙钟，不是独立 C CPU 周期。调度延迟是实际开始减计划步进时间，单独量；快照不计入步进计时但会影响总 CPU/下次唤醒。P95 取直方图桶下界；CPU 按单核 100%；RSS 不代表泄漏，也不会在 free 后立即全部归还。压测不启动网络、游戏逻辑、AOI 或数据库。

## 自动化验收
真实 Skynet 日志 `logs/skynet-test.log`。20/60 Hz 均执行正面反弹、斜向碰撞转动、推动静止车、不同质量、撞边、8 车连续碰撞、油门/转向/松手减速和销毁重建，共 16 条断言用例通过；另有基线碰撞断言、Actor 隔离和异常测试。仓库现有服务不改动，客户端不改动。

### 容量与资源回收
- **20 Hz：至少 128 个 8 人房间**完成 60 秒、零漏步。该组总计 153,600 步，调度 P95 10.3 ms，最坏 17.06 ms；CPU 为单核的 24.90%，峰值到退出后 RSS 为 93.0 → 16.8 MiB。
- **60 Hz：至少 128 个 8 人房间**完成 60 秒、零漏步。该组总计 460,800 步，调度 P95 11.6 ms，最坏 17.62 ms；CPU 为单核的 40.56%，峰值到退出后 RSS 为 92.9 → 17.4 MiB。

128 房间从 20 Hz 升到 60 Hz，CPU 从单核 24.90% 增到 40.56%（1.63 倍）；60 Hz 最坏调度延迟 17.62 ms，超过一个 16.67 ms 物理步，但累加器追赶后未丢步。20 Hz 的同档最坏调度延迟 17.06 ms，在 50 ms 预算内。
这是本机在这套脚本下观测到的容量，不外推到生产，也不表示每次都在一个时间步预算内；以 P95、最大调度延迟和漏步同时判断。上限仅测到 128 房间；没有检验更大规模或长跑。每组都检查 Room 已退出（成功组）；RSS 回落仅是观察项，不能证明 C 层零泄漏。

### 与现有碰撞计算的成本
- 20 Hz / 1 房间：整步 Moon / Lua 平均 193.59 / 411.58 µs（0.47×），单核 CPU 2.45% / 2.44%。
- 20 Hz / 32 房间：整步 Moon / Lua 平均 49.02 / 336.98 µs（0.15×），单核 CPU 8.23% / 25.89%。
- 20 Hz / 128 房间：整步 Moon / Lua 平均 44.88 / 352.47 µs（0.13×），单核 CPU 24.90% / 101.51%。

纯 Lua 组使用原项目源码（锁定 commit 和模块 SHA-256），共享 8 车布局、油门/转向、步数和采样频率。原算法使用圆形车辆、圆形边界和固定冲量；此 POC 使用矩形刚体、方形墙、质量/旋转/接触材料。轨迹和碰撞次数会不同，结果反映这两个实现的量级，不是等价物理计算或完整游戏端到端基准。
在 128 房间／20 Hz 对照里，Lua 求解回调累计记录约 114 万个事件，Moon 开始接触记录约 1.64 万次；事件定义不同，且脚本持续驱动车辆聚集，不能把这里的近 8 倍整步差异当成生产提升。相同档位 Moon 峰值 RSS 约 93 MiB，Lua 对照约 57 MiB。

## 失败与未验证
- GCC 14 构建 Chipmunk2D 时对上游 cpBBTree 的分配尺寸范围发出警告，未阻断构建；未做 sanitizer 或极端对象数下的专项验证。
- 上游未修改版本对 Lua 5.5.1 编译失败；原生环境第一次 Skynet 编译因缺 autoconf 失败，随后补齐本地工具后完成同版本 bundled jemalloc 构建。日志按尝试保留。
- 原生 POC 没有运行 Docker 或发布镜像；没测试真实在线速度、网络边界、持续运营、内存 sanitizer 或 ARM64/macOS 原生。
- 附独立 Dockerfile 供自行尝试，未运行，不用于本报告任何通过结论。
