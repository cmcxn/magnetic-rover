# 微信小游戏最小联机验证

这是技术验证客户端（在开发者工具运行，默认连接远端服务），保留 Phaser 3.90.0，复用 `client/src/world.ts`、`motion.ts`、`types.ts`，连接现有 Skynet `/ws`。与 H5 共用场景和运动代码，服务端规则保持不变。画布 UI 替代网页 DOM；通过 `wx.connectSocket`、微信存储和触控 API 工作。使用 Canvas 渲染，声音使用微信原生 `wx.createInnerAudioContext`；首次触摸解锁，提供声音开关。

## 构建和运行

在项目根目录执行（需要 Docker；不要求宿主安装 Node/npm）：

```sh
./scripts/build-wechat.sh
```

微信开发者工具导入本目录 `minigame/`，不要只导入 `dist/`。项目类型为小游戏，代码根目录为 `dist/`，横屏。使用工具提供的测试号；配置中的 AppID 由本机工具选择的测试号写入，不是正式发布 AppID。选择“不使用云服务”，信任本项目并运行。

1. 点击“连接：微信车手”，再“创建房间”。
2. 用网页 `https://cb.chenmin.org/` 加入同一房间，或使用另一个真实 WebSocket 测试客户端。两端必须连接同一个服务器。
3. 双方准备后，服务器开始 100 秒比赛。
4. 拖动场地驾驶，点击“冲刺”；货物、积分和比赛结束由服务器快照决定。
5. “离开房间”返回大厅；断开后可手动重新连接。游客凭证仅保存在端点专属的微信本地存储中。

修改源码后重新构建，在开发者工具点击“编译”。首次进入先显示资源分包下载进度，成功后显示游戏；加载失败可重试。入口及游戏代码统一编译到 ES2017，避免模拟器接受而上传校验拒绝可选链等语法。构建中的 `package-size.mjs` 检查主包预算和分包入口。`dist/` 与工具生成的 `project.private.config.json` 不入库。

默认地址是 `wss://cb.chenmin.org/ws`，复用已部署的 HTML5 服务端，不要求手机和电脑在同一个 Wi-Fi。微信小游戏代码/资源从本地包加载，游戏消息直接发到远端 WSS，不嵌入网页。服务器已有可信 TLS 和 WebSocket Upgrade；此客户端不部署或修改远端服务。

登录页“服务器设置”的已保存地址优先于默认地址；若曾保存本机地址，请在此处改成上述远端地址，再重新编译。模拟器存储与手机存储独立。

如需本机后端，可执行 `docker compose up -d --wait`，再把服务器设置为 `ws://127.0.0.1:18080/ws`。手机上的 `127.0.0.1` 是手机自身，本机模式真机测试应填写电脑可达的局域网 IP。

当前测试工程仍关闭了开发工具的域名校验；模拟器 WSS 联通不等于完成微信后台白名单配置。正式 AppID 的手机预览/发布需配置 `wss://cb.chenmin.org` 为 socket 合法域名，并按微信要求验证证书与域名权限。

## 与发布结合

发布时，`dist/` 里的代码和随包资源上传微信，由微信分发。Skynet 可以只保留 WebSocket 权威服务；现有 HTTP 静态页面可以继续供网页玩家使用。大型图片/音频也可以另外放到 HTTPS 资源服务器，本验证版将图片放在微信 `art` 资源分包，启动时通过 `wx.loadSubpackage` 加载成功后再启动 Phaser，不依赖自建资源 CDN。

正式上传之前仍需：自有小游戏 AppID 与开发者权限、合法域名和可信 TLS/WSS、真实设备验收以及微信后台要求的发布资料。已将三张原始 PNG 移到 `art` 分包：主包约 1268 KiB、资源分包约 3191 KiB。构建会自动检查主包小于 4 MiB，超限时直接失败；所有包的总量约 4459 KiB 不再计为一个主包。这仍是验证版，不代表已满足所有提审条件。

## 验证边界

2026-10-28 已在微信开发者工具 2.02.2609240、基础库 3.17.5 的 iPhone 12/13 模拟器横屏环境启动 Phaser 场景。真实 `/ws` 验证过连接、创建房间、第二端加入、准备开局、触控移动和完整比赛结算。第二端按正常输入协议采集/回收，服务器记录最高载货 6、得分 84；服务器记录微信端位移约 237 世界单位。第一轮手动操作未验证微信玩家自身的采集/回收。

远端验证（2026-10-28）：微信开发者工具直接使用 `wx.connectSocket` 连接 `wss://cb.chenmin.org/ws`，TLS 与 WebSocket Upgrade 成功；创建独立房间并与第二个真实 WSS 客户端完成 100 秒比赛，收到 1232 个房间快照（含大厅等待）。服务器记录微信端最高载货 4、位移约 429 世界单位；第二端最高载货 5、回收积分 80。微信端运行时确认端点为远端域名，快照持续更新，RTT 观察值约 44–61 ms。完成结算及自动返回大厅房间后已退出测试房间；未修改远端代码或部署。微信玩家自身回收计分尚未验证。

尚未验证：实体手机、手机间联机、性能/续航、实体手机音效播放、网络切换、正式版本上传/审核。已在当前测试号成功上传预览包并生成手机预览二维码，未提交审核或正式发布；实体手机启动仍待用户扫码验证。

预览包修复验证（2026-10-28）：旧主包约 4456 KiB 的超限已由 `art` 资源分包解决。新构建主包约 1268 KiB、资源分包约 3191 KiB；开发者工具确认分包加载和 Phaser 场景初始化成功。预览上传过程中另发现上传校验不接受可选链，已统一转译到 ES2017。再次点击“预览”后上传成功，显示可供手机扫描的二维码（界面总包约 4457 KB）。启动等待资源、加载失败不启动游戏、重试后启动的入口检查通过；现有前端 125 项测试通过。

只读控制台诊断：在开发者工具 Console 选择 `gameContext` 后执行 `JSON.stringify(GameGlobal.roverSpike)`，可看连接、房间、玩家位置/分数、RTT 和快照新鲜度，不包含游客凭证，也不提供改变得分或位置的调试接口。HUD 显示渲染器和 FPS，诊断对象还提供 `frameSample`（FPS、p95/p99 帧间隔、超过 50 ms 的长帧计数）和 `scenePeakMs`。这些是渲染循环/场景耗时观测，不是 GPU 执行时间或屏幕实际刷新率。

## 运动跳动与时钟修复（2026-10-28）

旧 quickstart 适配器的 `performance.now()` 实际返回 `Date.now()/1000`（秒），而共享运动预测、快照插值和 Phaser 时钟使用毫秒。在开发者工具中复现：真实经过 253 ms，游戏时钟只前进 0.253；此时渲染循环仍约 55 FPS，因此不能把小车跳动直接等同为渲染掉帧。

适配器现使用单调递增的 elapsed milliseconds，并让 RAF 回调复用同一时钟，避免 native RAF 的时间原点/单位差异。修复后实测：260 ms 对应游戏时钟 260，RAF 与 performance 时间差为 0。没有改动服务器频率、协议或游戏规则，渲染器仍为 Canvas；尚未证明手机渲染性能提升。

`tests/clock.test.mjs` 执行实际适配器，验证毫秒时间、RAF 一致性、时钟回拨和共享 Motion 在两个权威快照间的连续运动（240 单位/秒：50 ms 约 12 单位，100 ms 约 24 单位）。构建先运行这 4 项测试，全部通过才生成分包；现有网页前端 125 项测试也通过。手机需扫描新预览包再次确认体感。修复版已在远端独立房间复测，快照持续更新，第二端正常采集并回收得分 53；模拟器比赛/结算阶段观察到约 50–55 FPS、p95 约 19–21 ms，场景更新峰值样本约 1 ms，仍有少量长帧。没有手机前后对比数据，不能据此宣称全部卡顿已经消除。

## 第三方来源

- `vendor/weapp-adapter.js` 基于微信官方 [miniprogram-game-quickstart](https://github.com/wechat-miniprogram/miniprogram-game-quickstart)，提交 `fbbf1f83dfee104c9dc922630613b47b5f21a385`，MIT 许可证随附。本地补丁将 `performance.now()` 从秒修为单调递增的毫秒，并统一 RAF 回调时间线；其余适配实现沿用上游。
- Phaser 取自现有前端 lockfile，MIT 许可证随附。
- `src/platform.js` 是本项目针对 Phaser 的补充；不模拟完整 HTML/CSS。该早期适配器的真机兼容性仍需独立验证。


## 原生声音与半透明 HUD（2026-10-28）

六种 Kenney CC0 音效随 art/audio 分包分发，无需音频网络域名。构建时从已有 WAV 生成 22.05kHz 单声道 PCM16：收集/冲刺分别缩短至 0.22/0.28 秒并淡出，其余完整保留；源音频不修改。首次触摸建立固定六个原生音频实例，音效依据服务器快照触发，切后台停止、静音开关持久化，遵循手机系统静音开关。

Phaser 横幅可能仍显示 No Audio：这是关闭浏览器音频管理器以免与微信原生播放重复，不表示原生音效关闭。控制台有 `[rover] audio backend: wx.createInnerAudioContext`，首次成功播放后有 `[rover] native audio playback started`；只读 `GameGlobal.roverSpike.audio` 可查看 enabled、unlocked、contexts、played 和 error。没有接入背景音乐。

小地图固定左上角、半透明，在 375px 高横屏也显示。右下球形冲刺按钮半透明，服务器确认的冲刺阶段消耗液体，冷却阶段回充液面与外圈进度；估算到零不会越过服务器授权。

更新后重新编译并重新生成预览二维码，旧二维码不代表当前本机源码。测试包括原生音频 API 契约、六类快照事件、手势解锁、静音、前后台、WAV 编码与预算、水球几何和充能状态。真实手机扬声器、系统静音设置及双指触感须重新预览验证。

本轮验证：148 项自动检查通过，H5 与小游戏严格类型检查、两端构建通过；小游戏主包 1288 KiB，总包 3855 KiB。812×375 浏览器测试态已确认左上角小地图可见和声音开关可用；原生声音、冲刺液面动画的真机验收交由用户完成，未据此宣称手机扬声器已通过。
